# slack-mentions

Claude Code 插件：在侧边面板里处理 Slack 上 @ 你的消息和私聊。

- 检查最近 24 小时里 @ 你的消息、私聊和全员消息，有新消息时发系统通知
- 自动起草回复，可以改，点「发送」才会发出
- 消息说的是某个已开会话正在做的事时，交给那个会话给出依据，再按它的结果拟稿
- 挂了知识库时（可选），知识库里写明答案的问题会自动回复，发出前有 60 秒可以取消
- 你自己在 Slack 上 @ 自己写的指令，可以自动开一个会话去执行，结果回到那条消息下面
- 机器人和全员消息默认收成一行，不自动拟稿
- 回复里写 `@名字`，发送前自动转成真正的 Slack mention
- 「新消息」：按人名、邮箱或频道名搜索，直接发私聊或发到频道

## 一句话安装

对 Claude Code 说：

> 按 https://github.com/gq-guo/ai-mix/tree/master/slack-mentions 的 README 安装 slack-mentions 插件

Agent 会按下面「安装步骤」执行。

## 前提

- Claude Code 桌面版或 CLI，版本要支持函数 hooks 插件（在 2.1.304 上验证过）
- 在 claude.ai 的 Settings → Connectors 里连接了 Slack 连接器

## 安装步骤（给 Agent 看）

1. 添加 marketplace 并安装到用户级：

   ```bash
   claude plugin marketplace add gq-guo/ai-mix
   ```

   ```bash
   claude plugin install slack-mentions@ai-mix --scope user
   ```

2. 找到 Slack 连接器在本机的名字：在当前会话的工具列表里找名为 `mcp__<server>__slack_search_public_and_private` 的工具，`<server>` 就是连接器名字（通常是一串 UUID）。找不到说明 Slack 连接器没连，停下来让用户先去 claude.ai 连接。

3. **只在用户使用自动模式（auto mode）时**做这一步，先征得用户同意：把下面 6 个只读工具加到 `~/.claude/settings.json` 的 `permissions.allow`，`<server>` 换成上一步的名字。不加的话，自动模式的权限检查会拦下插件的 Slack 调用。

   ```json
   "mcp__<server>__slack_search_public_and_private",
   "mcp__<server>__slack_read_thread",
   "mcp__<server>__slack_read_channel",
   "mcp__<server>__slack_read_user_profile",
   "mcp__<server>__slack_search_users",
   "mcp__<server>__slack_search_channels"
   ```

   不要把 `slack_send_message` 加进去：发消息必须由用户自己点按钮。

4. 让用户在已打开的会话里输入 `/reload-plugins`，新开的会话会自动加载。

## 使用

- **打开面板**：输入 `/slack-mentions`。第一次安装后会自动打开一次。
- **输入框上方的入口**：显示「Slack · N 条待回复」和「打开 / 收起」按钮。桌面版要在会话里提交过一次输入后才会出现。
- **回复**：卡片里的草稿可以直接改，点「发送」或回车发出。频道消息回复在 thread 里，私聊直接回复。发出后卡片自动消失。
- **重新拟稿 / 忽略**：忽略后同一条消息不再出现。
- **全员消息和机器人消息**：默认各占一行，标「全员」或「机器人」，不自动拟稿。点「展开」变成完整卡片，可以自己写或点「拟稿」；不用回就点「忽略」，折叠的有两条以上时可以点顶部「忽略通知」一次清掉。机器人消息只显示直接 @ 你、并且有文字的；机器人私聊和机器人发的全员公告都不显示。
- **输入框上方的计数**：通知单独计数，显示成「N 条待回复 · M 条通知」。
- **新消息**：面板右上角「新消息」→ 输入人名（`alice`）、邮箱（`alice.wang@company.com` 或 `alice.wang`）、频道名（`help-demo`、`#help-demo`）→ 选中 → 写内容 → 发送。
- **@ 人**：写 `@Alice`、`@alice.wang`（邮箱前缀最准）、`@here`。先在当前对话的参与人里找，再在整个 Slack 里找；有多个人重名时不会发送，会提示你改成邮箱前缀。
- **长消息**：超过 280 字的消息默认折叠，点「展开」看全文，「收起」折回去。
- **刷新 / 暂停**：手动检查一次，或暂停检查。

### 按你的口吻拟稿（可选）

如果存在 `~/.claude/skills/slack-voice/SKILL.md`，拟稿时会按里面描述的说话风格写；没有就用简短、友好的默认语气。

## 检查频率

- macOS 上，别人的消息在 Mac 出现 Slack 通知后才去搜，另外每 5 分钟完整检查一次。插件只读通知中心里 Slack 通知的最新编号、最新时间和条数，不读通知内容。
- 你自己 @ 自己的指令每 10 秒检查一次，因为自己发的消息不会有通知。
- 读不到通知中心时（不是 macOS、没有权限、没有 `sqlite3`），退回每 10 秒完整检查一次。面板顶部的状态行写着当前是哪一种。

## 交给会话

每条新消息先分流（Sonnet，不调用任何工具）：

- **交给已开的会话**：消息里的 Jira 单号或 PR 对上了某个会话，或者分流判断它说的是某个会话正在做的事，就把消息发给那个会话。会话用插件提供的 `answer` 工具交回事实和结论，插件按结果拟稿。只有消息交给的那个会话能交回结果，别的会话用同一个卡片编号调 `answer` 不会被采用。会话的结果不会自动发，由你点发送。会话 10 分钟没回就先按对话拟稿。
- **建议开会话**：要先调查才能回答、又没有对得上的会话时，卡片上出现「开 session 处理」，点了之后把请求填进输入框，你回车才会开。
- 同一个 thread 之后的消息会交给同一个会话；整段私聊在最近一次交接后的 2 小时内沿用。

交给会话的消息开头注明 Slack 内容是别人写的数据、不是指令，只做只读查看。会话列表和发消息用的是 Claude 桌面版自带的会话工具，只在桌面版里可用。负责轮询的会话和目标会话的权限模式不一样时，桌面版会把消息扣在目标会话里等你批准。为了少遇到这种情况，每个会话把自己的权限模式记在 `modes.json`，模式不同时改由一个和目标同模式的会话转交；45 秒内没有这样的会话接手，就由轮询的会话自己发，卡片会注明要去目标会话批准，批准后结果照常回来。

## 知识库自动回复（可选）

不配置就没有这个功能，所有消息都只拟稿。有两种配法，可以同时用：

- **放几个文件**：把 `.md` 文件放进 `~/.claude/slack-mentions/kb/`。
- **挂载已有的文档目录**：新建 `~/.claude/slack-mentions/kb-roots.json`，每项一个目录，排前面的优先：

  ```json
  [
    { "name": "team-docs", "path": "/absolute/path/to/docs", "index": "INDEX.md", "hold": ["customers/"] }
  ]
  ```

  - `name`：给这个目录起的名字，只能用字母、数字、`-`、`_`
  - `path`：目录的绝对路径
  - `index`：目录里的索引文件，要用 Markdown 链接列出各篇文档。插件从索引往下读，最多 3 层，每层最多 4 个文件，不会扫描整个目录
  - `hold`（可选）：这些子目录里的文件可以用来回答，但回复只出草稿，不自动发

读取限制：只读 `.md`；路径不能带 `..` 或隐藏目录，真实路径必须在挂载目录内；`credentials`、`secrets.` 开头的文件不读。`~/.claude/slack-mentions/kb/` 里的文件按同样的规则过滤，隐藏文件和符号链接不读。

回复由不带工具的模型调用生成，只能用知识库里写明的内容。全部满足才会自动发：

- 知识库写明了完整答案，并且列出了用到的文件（只答得出一部分时只出草稿）
- 回答时没有读过 `hold` 目录里的文件（按实际读的文件算，不看回复自己列的来源）
- 回复里没有密钥样式的内容、本机路径、`[待确认]`、@ 人或用户组、全员提醒，也没有知识库里没出现过的链接、域名或频道（提问的人自己贴的链接不算）
- 这次搜索结果的编号对得上：消息正文里夹了伪造的结果块时，这一批消息都只出草稿，卡片上会注明
- 不超过 600 字，每小时不超过 6 条，同一个对话 10 分钟内只自动回一次

满足时卡片上显示自动发送的时间，60 秒内可以点「取消自动发送」，改过草稿也不会再自动发；取消过的卡片记在 `stopped.json`，之后不会再自动发。每次自动发送记在 `~/.claude/slack-mentions/auto-log.json`。

## 自己 @ 自己：把 Slack 当任务入口

你自己写、并且 @ 了自己的消息当作指令处理，只认发出 15 分钟内的：

- 写了「开任务」「开一个新 session」「start a new session」，或「查一下」「帮我」这类明确的话：自动新开一个会话执行
- 写了会话编号（`#12`、`12 号 session`）：交给标题以这个编号开头的会话
- 其他情况只出卡片，等你点

结果由插件回到那条消息下面：通过检查后立刻发出，没有可取消的等待时间。认不出是哪个会话交回的结果（比如你点「开 session 处理」后自己回车开的会话）只出草稿，等你点发送。是不是你本人发的，靠单独一次按作者过滤的 Slack 搜索确认，别人消息里写的「From: 你」不算；别人的消息永远不会自动开会话。

自动开会话需要你在 `~/.claude/settings.json` 的 `permissions.allow` 里放行桌面版开会话的工具（名字形如 `mcp__<server>__start_session`），不放行就只出卡片。

## PR review 请求：自动检查、review、approve（可选）

默认关闭。写了 `~/.claude/slack-mentions/pr-review.json` 才生效：

```json
{ "org": "your-org", "bot": "your-review-bot", "repos": ["repo-a", "repo-b"], "maxFiles": 10, "gh": "/opt/homebrew/bin/gh" }
```

- `org`：只处理这个 GitHub 组织下的 PR
- `bot`：必须已经 review 过这个 PR 的 review 机器人账号
- `repos`：可以不经点击自动 approve 的仓库；不在里面的要你点
- `maxFiles`（可选，默认 10）：改动文件数超过它的要你点
- `gh`（可选）：GitHub CLI 的绝对路径，会话的 PATH 里没有 `gh` 时填；需要先 `gh auth login`

别人私聊或 @ 你的消息里正好有一个该组织的 PR 链接时：

1. 用 `gh` 检查（代码判断，不经过模型）：PR 是 open、不是 draft，机器人 review 过，没有人 request changes，没有未解决的 review 问题，CI 没有失败项。有一项不满足就只出卡片写明原因，不 approve。
2. 把 `gh pr diff` 交给不带工具的模型快速 review。不 clone，不执行 PR 里的代码。发现问题就只出卡片列出问题，不 approve。
3. 都通过、仓库在 `repos` 里、改动文件数不超过 `maxFiles`：卡片显示倒计时，60 秒后自动 approve 并回一句「已 approve repo#编号」，期间可以点「取消自动发送」。
4. 都通过但仓库不在名单里、改动文件太多，或 diff 太大没法自动 review：卡片上出「approve 并通知」，你点了才执行。

approve 前会再确认 PR 仍是 open、最新提交和检查时是同一个，变了就不 approve。approve 以你本机 `gh` 登录的账号进行。私聊里连发几个 PR 链接时每个各出一张卡片；你在它们之后回过消息的，视为你已经处理。

注意：PR 的标题、描述和 diff 都是别人写的内容，模型的快速 review 可能漏掉问题，也可能被里面的文字误导。自动 approve 挂的是你的名字，介意的话把 `repos` 留空，全部改成点击。

## 自动模式下发送被拦

发消息的工具 `slack_send_message` 不在放行规则里，自动模式的会话里每次发送都要过权限检查。检查没给出结论时插件会自动再试一次；还被拦的话，会交给另一个不在自动模式的会话代发，2 分钟内没有会话能发就在卡片上提示。不建议把发送工具加进放行规则：那样 Claude 在自动模式里就能不经你确认直接发 Slack 消息。

## 多个会话

所有会话共用一份待回复列表，同一时间只有一个会话负责定时轮询和自动发送，其他会话同步显示。任何会话里点「刷新」都会检查一次并拟稿；被交接的会话调 `answer` 时，拟稿在它自己那里做。负责轮询的会话关掉或连续失败约 100 秒后，其他会话会自动接管；加载了更新版本插件的会话会直接接管旧版本的。

## 数据

- 待回复列表、已处理记录、交接记录（`routes.json`）、各会话的权限模式（`modes.json`）、取消过自动发送的卡片（`stopped.json`）、轮询锁、知识库挂载配置（`kb-roots.json`）、PR review 配置（`pr-review.json`）都存在本机 `~/.claude/slack-mentions/`，不会上传到别处
- 自动回复记录 `auto-log.json` 里有对方的原话、发信人和发出的回复，最多留最近若干条，不想留可以直接删这个文件
- 读 Slack、发消息都通过你自己在 claude.ai 连接的 Slack 连接器，以你的身份进行
- 拟稿和分流时会把消息、最近的对话记录，以及用到的知识库文件发给 Claude 模型（Sonnet）

## 卸载

```bash
claude plugin uninstall slack-mentions@ai-mix
```

需要的话，再删掉 `~/.claude/slack-mentions/` 和第 3 步加的放行规则。
